# Task Design Skill

## Purpose

Преобразовать проанализированные требования в структурированный набор задач в Jira.

## Inputs

- Проанализированные требования, включая бизнес-логику и нефункциональные требования.
- Контекст проекта в Jira
  - Project Key или ссылка на проект
  - ID Эпика (необязательно)
  - версия релиза/спринта (необязательно)
- Assignee (не обязательно)

## Procedure

1. Логическое разделение требований на функциональные блоки
2. Формирование полей задач:
   - **Summary**: Краткое и емкое описание по стандарту: `[Модуль] выполняемый функционал`
   - **Description**: Подробное описание в виде структурированного чек-листа критериев приемки (Acceptance Criteria).
   - **Epic** — если в Inputs указан ID Эпика, заполнить значение, иначе оставить пустым
   - **Assignee** — если в Inputs указан Assignee, заполнить значение, иначе оставить пустым.
3. Исключить из сформированных задач уже существующие в Jira
4. Создание в Jira только тех задач, которые не исключены в предыдущем шаге

## Rules

- Задачи должны быть атомарными и понятными.
- Не модифицировать полученные требования.
- Каждая User Story в Description обязана содержать четкие, проверяемые Acceptance Criteria.
- Не удалять / не изменять уже существующие в Jira задачи.
- Не создавать дублирующиеся задачи.

## Output

Структурированный отчет по созданным задачам в следующем виде:

- **Сводка**: количество созданных задач по типам.
- **Таблица маппинга**:

| Требование | ID задачи (Jira) | Summary | Краткое содержание указанной в требованиях функциональности |
|------------|------------------|---------|-------------------------------------------------------------|
| ...        | PROJ-101         | [Модуль] функционал | ...                                                         |

- Ссылки на созданные задачи
- Список задач, похожих на уже существующие в Jira
- Список требований, которые не удалось преобразовать в задачи

## Completion Criteria

- Все провалидированные требования полностью покрыты созданными задачами без пропусков.
- Все неоднозначные и противоречивые требования вынесены в отчете 
- Задачи атомарны и понятны.
- Каждая задача содержит Summary и Description с проверяемыми Acceptance Criteria и остальные поля, если таковые заданы.
- Все созданные задачи успешно прошли валидацию Jira API и созданы.
- Сформирован структурированный отчет.
